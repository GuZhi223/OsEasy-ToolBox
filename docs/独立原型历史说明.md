# OsEasy Auto

针对当前教室样本的 Windows 桌面自动模式预览版。默认自动处理已支持的本机事件，保留窗口广播，并显示事件记录。

本次打包产物为 **64 位 Windows 程序**，可连接 32 位学生端；本机验证环境为 Windows 11。

## 试用

1. 将 `dist/OsEasyAuto.exe` 复制到教室电脑，双击打开。无需安装 Python。
2. 点击 **开启自动模式**。需要时会弹出 Windows 管理员启动提示；工具识别当前正在运行的学生端，无需填写教师 IP。
3. 收到已支持的广播请求后，自动调整参数和窗口。可使用 **临时全屏 / 返回窗口**，或收起到托盘。
4. 点击 **停止并恢复**，或关闭窗口，停止本次监听并恢复本次修改的窗口状态。

第一轮请测试“广播开始 → 窗口观看 → 广播停止 → 再次开始 → 停止并恢复”，并查看界面事件记录。

## 第一版实际覆盖

| 能力 | 已实现的行为 | 边界 |
|---|---|---|
| 样本识别 | 按程序和相关 DLL 的 SHA-256 校验，绑定进程 PID、启动时间和实际路径 | 限定本项目记录的样本；构建路径标签为 `10.9.1.5433`，不是从产品界面确认的版本号 |
| 持续事件接收 | 连接 `MmcStudent.exe`、广播进程和样本中的设备控制辅助进程；进程退出后重新识别 | 不等同于获取教师端所有操作 |
| 广播窗口化 | 在已核验路径的广播启动请求中调整全屏参数；为已运行的对应广播窗口添加边框并取消置顶 | 创建请求调整和窗口效果核验分别记录；实际课堂播放仍需实测 |
| 快捷键限制新请求 | 对明确的 `OeKbdFilter` 设备、控制码、包类型及长度组合拒绝新的限制调用 | 对应 Alt/Win/Ctrl 类受限键列表，不能宣称涵盖所有键鼠锁定；已有驱动状态未重置 |
| 网络限制新请求 | 在已核验且加载的 DLL 中拒绝 `DisableInternet` 调用 | 只覆盖该已定位接口；已有网络限制不主动解除 |
| USB 限制新请求 | 在已核验且加载的 DLL 中拒绝 `EasyUsb_StartWorking` 调用 | 不主动调用带注册表写入的开关接口；已有 USB 限制不主动解除 |
| 恢复 | 卸载本次进程内监听/处理，核验窗口样式恢复；恢复失败保留记录 | 不声称把未知的既有驱动状态还原为其他状态 |
| 黑屏、其他远程控制和已有锁定 | 界面标记待适配 | 当前没有可靠覆盖，不显示“全部脱离管控” |

界面中的“监听已接入”指观察点已建立；只有窗口处理经过核验时才显示相应成功记录。“拒绝了新请求”表示指定调用已经返回失败，不能作为已解除此前限制的证明。

此前用户已确认原 OsEasy-ToolBox 可以在教室实机正常运行；本预览版是新的实现，不能把旧版实测结果当成这份 EXE 的实测结果。如果原工具箱已替换 `ScreenRender.exe`，新程序会拒绝把该替换文件识别为原厂渲染器。应恢复原厂文件状态后测试本程序的广播链，避免两套自动处理同时操作同一组件。

## 运行机制

程序在本次会话中使用 Frida 建立进程内观察点，结合 Win32 窗口 API 处理广播。学生端继续接收事件；本实现没有使用长期挂起主进程作为默认操作。

对网络/USB 新限制请求的拒绝不会执行原接口，因此不会由这些被拒绝的调用写入驱动或注册表。停止后，函数调用恢复为原程序行为；程序没有主动重置已有驱动状态。

状态和本机事件记录位于 `%LOCALAPPDATA%/OsEasyAuto/`：

- `events.jsonl`：最近事件和错误，不记录完整广播参数或远程命令参数。
- `events.previous.jsonl`：轮换后的上一份记录。
- `recovery.json`：窗口原状态。异常退出后，下次开启时先处理待恢复窗口。

主界面可同时打开，但同一 Windows 会话只允许一个自动控制器运行。标准用户在点击开启时通过正常 UAC 流程重新启动，不绕过权限检查。

## 开发

本地使用 Python 3.12（64 位）：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe run.py
```

只看交互演示：

```powershell
.\.venv\Scripts\python.exe run.py --demo
```

只读探测与独立自检：

```powershell
.\.venv\Scripts\python.exe run.py --probe
.\.venv\Scripts\python.exe run.py --self-test
```

`--self-test` 只连接本程序新建的测试进程，不启动教室样本。
