## 本项目的主交互

主界面保留三个区域：

1. **状态**：未开启、正在准备、自动模式运行中、部分功能未就绪、正在恢复。
2. **主操作**：未运行时显示“开启自动模式”；运行时显示“恢复并退出”。收到广播时出现“临时全屏 / 返回窗口”操作。
3. **事件记录**：显示本机收到或观察到的事件、处理结果和时间。成功自动处理的重复事件合并显示；需要人工介入或处理失败时给出具体原因。

日常使用不再要求手工输入教师 IP、复制广播命令、切换多个功能页、猜测先停哪个进程。已有的手工诊断入口放入高级设置，供出现具体故障时使用。

自动启动流程：

```mermaid
flowchart LR
    A[开启自动模式] --> B[识别当前样本与环境]
    B --> C[建立事件来源并保存原状态]
    C --> D[应用默认策略并核验]
    D --> E[持续处理新事件]
    E --> F[恢复并退出]
```

只有核验完成的能力才显示为已生效；进入监听状态本身不等于所有管控都已经处理。

## 默认行为与实现证据边界

| 场景 | 用户期望的默认行为 | 当前证据与后续验证 |
|---|---|---|
| 老师开始广播或再次发起全屏 | 自动保留可拖动、可缩放的窗口广播；不要求手填参数 | 样本含 `ScreenRender.exe`，已有广播参数字符串和原工具箱流程；持续捕获来源及完整生命周期尚需验证 |
| 老师停止广播 | 同步结束相应的窗口广播和会话记录 | 必须绑定对应会话，不能依靠固定延时或猜测 |
| 锁定键鼠、黑屏、远程控制 | 自动按已启用策略处理，并记录成功或失败 | 用户报告整体可用；具体功能覆盖及噢易实现位置尚未逐项细分 |
| 网络或 USB 管控 | 按已启用策略自动处理，处理失败时明确显示 | 样本 DLL 与部分导出名已确认；权限、ABI 和实时状态尚需现场验证 |
| 学生端重启或重新连接 | 自动重新识别目标进程和对应会话 | 绑定进程启动时间和路径，防止 PID 复用误认；不得影响无关同名程序 |
| 退出自动模式 | 恢复本次会话实际改变的项目并报告恢复结果 | 通过操作日志和原状态快照核验，不能用“已发送恢复命令”代替完成 |

未知事件显示为“已观察到，尚未支持”，不能显示为“已拦截”。远程启动程序、关机等行为若要纳入自动策略，需要先建立明确的事件来源、动作定义和核验方法。

## 最关键的架构约束：持续事件来源

原工具箱中存在挂起学生端、替换广播程序、读取日志等相互独立的操作。把按钮简单串联，未必满足持续自动处理的目标。

如果后续事件依赖 `MmcStudent.exe` 接收并处理，而一键流程已经把它长期挂起，则这条事件链可能随之停止。此时不能承诺仍能通过该进程自动获知新的教师操作。

自动模式进入“运行中”之前，应先建立并确认至少一条持续有效的事件来源。已发现的广播日志、进程启动和窗口变化可用作候选观察点；它们通常反映本机发生的结果，不能自动等同于管控指令生效前的拦截点。是否需要噢易专属的内部接口适配，应以该样本的实际调用链为依据。

窗口广播、键鼠锁定、网络和 USB 等事件不应因为名称相近就被假设为同一种协议或同一个 DLL 接口。它们分别登记能力和健康状态。

## 模块分工

| 模块 | 职责 |
|---|---|
| 样本识别 | 校验 `oseasy_auto/assets/target.json` 中的文件指纹、路径和进程身份；构建号只是辅助标签 |
| 环境与能力探测 | 读取进程、窗口、服务和组件状态，标明当前有哪些可用能力及前置条件 |
| 事件采集 | 将确定来源的本机事件转换为统一记录，维护广播会话与进程生命周期 |
| 策略引擎 | 按用户选择决定自动动作，处理重复事件、暂时全屏和暂停等状态 |
| 动作执行与核验 | 调用经验证的适配动作，检查结果，保存可恢复的原状态与操作日志 |
| 桌面界面与托盘 | 显示主开关、实时状态、窗口广播操作和事件记录 |

统一事件至少包括：事件类型、来源、进程身份、会话标识、观察时间、拟执行动作、执行结果和核验状态。未执行、执行中、执行失败和已经核验成功必须可区分。

执行由单一串行队列协调，事件采集与界面保持响应。同一广播启动事件去重，重试采用有限次数与退避；恢复失败的项目单独报告。

## 一键启动与恢复的约束

- 一次点击触发完整准备流程，连续点击不能重复替换文件、创建重复监听器或覆盖原状态快照。
- 记录本次修改前的值，并且只恢复本次工具实际修改的项目。
- 需要注销或重启的旧操作要被明确识别，不能把要求重新登录的流程显示为已经在当前会话全部生效。能否替换为当前会话中的处理方式仍需验证。
- 已被用户验证的原工具箱能力先作为可复用实现依据；静态目录差异仅用于诊断，不自动禁用已知有效行为。
- 未取得事件来源、动作结果或恢复结果时，界面保持对应的未就绪状态，不以固定等待时间伪造成功。

## 验收场景

1. 启动后无需复制命令或填写教师地址，界面准确显示已就绪的能力。
2. 广播连续开始、停止、再次开始时，每次只对应一个窗口和一条会话，重复事件不造成反复启动。
3. 自动模式运行中仍能持续观察后续事件；暂时全屏后能返回窗口。
4. 学生端重启后识别新进程，旧会话关闭，监听状态明确更新。
5. 每类启用的管控策略均有独立的实机效果验证；未覆盖功能不标记为成功。
6. 恢复并退出后，本次修改逐项核验；若原状态无法恢复，显示准确的失败项目。

具体界面框架与底层适配方式在事件链证据明确后选择。此阶段已经确定产品行为和模块边界，没有把极域的 Hook 代码当作已适配噢易的实现。
